# 自动判分规则

出卷人和判分代码之间的**约定**。写卷子时按这里的写法填，判分结果就是确定的；
反过来，判分出现“不该错却错了”，先对照这份表。

代码在 `api/src/lib/exam.js`：`normText` / `judgeTruth` / `lettersOf` / `gradeOne` / `autoGrade`。

---

## 一、五种题型，各自的答案写法

| 题型 | `type` | `answer` 怎么写 | 自动判 |
|---|---|---|---|
| 单选 | `choice` | `"B"` | ✅ |
| 多选 | `choice` | `"ABD"`（字母连写，顺序随意） | ✅ |
| 判断 | `judge` | `"对"` / `"错"` | ✅ |
| 填空 | `fill` | 标准答案 + `accepts: [...]` | ✅ |
| 简答 | `short` | 参考要点（不参与判分） | ❌ 老师手工 |

**单选还是多选，是答案里有几个字母决定的**，不另设字段：

```
answer = "B"    → 单选（前端渲染圆点）
answer = "ABD"  → 多选（前端渲染方框）
```

---

## 二、选择题（choice）

### 归一化

学生的作答会被这样处理：

```
去除非 A-Z 的字符（括号、点、空格、中文全不要）
→ 转大写
→ 去重
→ 排序
```

所以这些都判对：

| 学生的作答 | 归一后 | 说明 |
|---|---|---|
| `B` | `B` | 正常 |
| `b` | `B` | 小写 |
| ` B) ` | `B` | 带括号标点 |
| `（B）` | `B` | 全角括号 |
| `DBA`（答案是 `ABD`） | `ABD` | **顺序无关** |

### 多选的部分分

段上写 `"partial": true` 才启用，**默认关闭（全对才给分）**。

| 情况 | 得分 |
|---|---|
| 全选对 | 满分 |
| **漏选**（有正确项没选，但没选错项） | `score × 选对数 / 正确答案数`，保留 1 位小数 |
| **选了任何错项** | **0 分**（不管选对几个） |
| 什么都没选 | 0 分 |

例：答案 `ABD`（3 项），每题 10 分，开了 `partial`

```
答 ABD  → 10 分
答 AB   → 10 × 2/3 = 6.7 分   （漏选 C）
答 A    → 10 × 1/3 = 3.3 分   （漏选 BD）
答 ABE  → 0 分                （E 是错的，一票否决）
答 CDE  → 0 分
```

**为什么选错一票否决**：多选的设计意图是“知道哪些对、也知道哪些不对”。
蒙对一个不算掌握；漏选只是没看全，性质轻得多。这是国内外标准化考试的通行做法。

> 单选题即使写了 `partial: true` 也不会给部分分（1 个字母没法拆）。

**想看效果**：导入 `判分演示-部分分.json`。它有一段开了 partial、一段没开，
同一道「漏选」在两边分别是 6.7 分和 0 分，直接对照。

```js
{ "type": "choice", "score": 10, "partial": true,  "questions": [ … ] }   // 漏选给比例分
{ "type": "choice", "score": 10, "questions": [ … ] }                    // 默认：全对才给
```

## 三、判断题（judge）

标准答案写 `"对"` / `"错"`，学生答对这些都算对：

| 判“对” | `对` `是` `正确` `真` `true` `T` `yes` `Y` `1` `√` `✓` `∨` `right` `correct` |
|---|---|
| 判“错” | `错` `否` `错误` `不正确` `假` `false` `F` `no` `N` `0` `×` `✗` `x` `wrong` `incorrect` |

**大小写不敏感，前后空格自动去掉。**

认不出的写法（比如 `也许`）→ 0 分，`why` 写「答案认不出（要填对/错）」。

---

## 四、填空题（fill）

判分建立在**归一化**上。学生写的东西先经过这四步，再和 `answer + accepts` 逐字比对：

| 步骤 | 做什么 | 例子 |
|---|---|---|
| ① | 全角字母数字 → 半角 | `ｒｅｆ` → `ref` |
| ② | 全角标点 → 半角 | `a（b）` → `a(b)` |
| ③ | **去掉所有空白**（含全角空格） | `re f` → `ref` |
| ④ | 转小写 | `Ref` → `ref` |

**不归一化符号本身**：

```
答案是 ref
学生写 ref()   → 判错    ← 括号是答案的一部分，不猜
```

要让它也算对，就在 `accepts` 里写出来：

```json
{ "id": "f1", "stem": "…", "answer": "ref", "accepts": ["ref()", "Ref", "vue 的 ref"] }
```

`accepts` 里的每一项**也走同样的归一化**，所以不用考虑大小写和空格。

**为什么不去掉括号/标点**：填空题经常考的就是“写对形式”（`ref()` 和 `ref` 在 JS 里不是一回事）。
自动去掉等于替学生做题，误判比不判更糟。**宁可要求老师在 `accepts` 里多列几种写法**。

---

## 五、简答题（short）

**不自动判**，`answer` 当参考要点显示给老师看。

- 学生交卷后这道题状态是 `pending: true`
- 老师在判分界面逐题给分（可以给 0 到本题满分之间的任何数）
- 全部判完，`total` 才完整

---

## 六、卷面分与折算

```
卷面分 = Σ(每段抽题数 × 段分值)
```

- **固定卷**：`fullScore` 用 JSON 里写的值（可以出 80 分小卷）
- **题库卷**：`fullScore` **按 pick 重算**，JSON 里写的不作数（写了会提醒）

判分后：

```
客观题自动分 + 老师给的主观题分 = 卷面得分（不超过 fullScore）
卷面得分 × 方案里的折算系数 = 计入「机试」项的分数
```

## 七、判分结果里有什么

`autoGrade()` 返回每题一条：

```js
{
  qid:      'c1',
  section:  's1',
  type:     'choice',
  score:    10,        // 本题满分
  given:    'AB',      // 学生答的（原样）
  answer:   'ABD',     // 标准答案
  explain:  '…',       // 卷子里的解析
  ok:       false,     // null = 主观题还没判
  pending:  false,     // true = 等老师判
  why:      '漏选，选对 2/3 项，按比例给分',   // 为什么是这个分
  got:      6.7        // 实际得分
}
```

**`why` 是给学生申诉和老师解释用的**——不用回头猜“这题为什么扣了 3.3 分”。

## 八、几个容易踩的点

**① `score` 在段上，不在题上**

```json
{ "type": "choice", "score": 6, "questions": [ … ] }    // ✅
{ "type": "choice", "questions": [{ "score": 6 }] }     // ❌ 不生效
```

**② 多选答案不要写逗号或空格**

```
"ABD"   ✅
"A,B,D" ✅（会被归一掉，也能用，但不推荐）
"A B D" ✅（同上）
```

**③ 判断题答案别写 `"正确"` 之外的自由文本**

`"对"` / `"错"` 最稳。写 `"正确"/"错误"` 也认，但别写 `"这个说法是正确的"`。

**④ 填空题的 `accepts` 宁可多写**

自动判错一次，老师就要手工改一次。`ref` / `ref()` / `Ref()` 都列上，成本很低。

**⑤ 段里题池不够 `pick` 会校验不过**

题库卷 `pick: 5` 但题池只有 3 道 → 导入时直接报错，不会生成残缺的卷子。
