# 接口请求审视（请求设计 + 前端行为）

> 方法：在真实浏览器里用 `performance.getEntriesByType('resource')` 采集每个页面的
> fetch/XHR（URL、传输字节、次数），同时用后端接口直接量 payload 构成。
>
> **一个关键前提**：整页刷新和 SPA 内切换要分开看。
> 早期我用 `goto` 逐页采集，结论是"每页都重复拉 40KB"——那是假象（整页刷新当然重来一遍）。
> 用内存标记（`window.__marker` 在导航后是否还在）确认了侧栏走的是 `router-link` 真 SPA 之后，
> 布局级请求不会重复，**只有页面级数据会重新拉**。

---

## 一、结论（改前 → 改后）

| 场景 | 改前 | 改后 | 变化 |
|---|---|---|---|
| 学生端首屏（分数页） | ~22KB / 9 个请求 | **12KB** | **-45%** |
| 教师端班级页 | ~346KB / 6 个请求 | **~75KB** | **-78%** |

明细：

```
学生端首屏
  /api/scheme      9.0KB → 1.9KB   加 ?brief=1，只取导航要用的
  /api/bootstrap   7.4KB → 3.0KB   学生端不再返回 items（4.6KB 的分值表头）
  /api/student/score 4.0KB（不变，这是页面真正要的）
  timetable / me / cast / presence / spotlight 各 0.3-1KB（全局，必要）

教师端班级页
  /api/classes/:id/scores  322.9KB → 52.3KB
    └ board.list[].rows[].item 原本带完整考核项（rule.params / hint / presets / hintTemplate），
      60 个学生各重复一份 = 306KB；而前端只用 item.key 和 score
```

## 二、三类问题

### 1. 多内容（一次给了用不到的）

| 接口 | 问题 | 处理 |
|---|---|---|
| `GET /api/scheme` | 8.3KB，其中 `raw` 3.4KB + `rules` + `forms` 只有**方案编辑器**用；学生端只拿 `modules`（0.9KB）渲染侧栏 | 加 `?brief=1`，学生端用精简版（1.9KB），教师端保持完整 |
| `GET /api/bootstrap` | 7.4KB 里的 `items`（4.6KB）是「各项考核的分值表头」，只有**教师端班级页**用；学生端读分数走 `/api/student/score` | 按角色裁剪：学生端 `items: []` |
| `GET /api/classes/:id/scores` | 306KB 是同一份考核项定义重复 60 遍 | 响应里瘦身 `rows[].item` 为 `{key,name,short,full,extra}`，**不动 computeClass**（分数榜/抽屉/导出还要完整对象） |

### 2. 无关请求

| 现象 | 判断 |
|---|---|
| `/api/pgsync` 在**每个**学生页都拉 | 目的只是"学生中途进来时老师可能已经在同步，主动问一次并自动跳转" —— 这个判断本身是合理的，但**字段读错了**（见下） |
| `/api/spotlight`、`/api/cast/status`、`/api/presence/ping` 每页都在 | **不是每页一次**，是定时器（`setInterval`）+ 布局常驻。SPA 内切页不会重发，属于必要开销 |

### 3. 过早请求

未发现。所有页面级数据都在页面 `onMounted` 里拉，没有"进首页就把别的页面数据一起拉"的情况。

**发现一个反例**：`StudentLayout.onMounted` 读的是 `r.pg`，而接口字段早已改成 `sync` →
`if (pg && pg.active)` 恒为假，**「学生中途进来自动跟上老师投屏/同步」这条从来没生效过**。
它不是请求太早，是请求发了但结果被丢掉。已修。

## 二之一、登录页：从 3 个请求 4.6KB → 1 个请求 0.36KB

任何人（未登录）打开 `/login` 时，原来会发三个请求，其中两个白给：

| 请求 | 大小 | 登录页用得上吗 |
|---|---|---|
| `/api/public/course` | 2.13KB（20 课次标题 + 课程名） | ✗ 一个字段都没用 |
| `/api/bootstrap` | 2.48KB（lessons + courses） | ✗ 拉完什么也没做 |
| `/api/courses/public` | 0.36KB（课程名列表） | ✓ 这个才是要的 |

### 两个来源都是死逻辑

**1. `App.vue` 无条件 `onMounted(() => bootstrap())`**

`store.bootstrap()` 的游客分支会拉 `/api/public/course`（带着完整课程目录），
但那份 `lessons` 唯一的用处是「课程材料」页的左侧目录。
→ 改成游客分支**什么都不拉**，需要课次清单的页面自己调 `loadPublicLessons()`。

**2. `Login.vue` 里的 `if (!state.classes.length) await refresh()`**

`state.classes` 在登录页**恒为空**（游客档本来就不给班级），
所以每次进登录页都白拉一次 `/api/bootstrap`，拉完什么也没做。已删。

### 顺带收紧的两处

- `/api/courses/public` 不再返回 `classes`（几个班）和 `students`（总人数）
  → 登录页页脚原来显示「1 门课，117 人次」，
  等于**任何人打开登录页就能知道这个学校有几个班、多少学生**。现在只显示「1 门课」。
- 游客能拿到的课程目录不再随登录页下发，只在真正要浏览材料时按需拉。

### 现在各入口的请求

```
登录页（游客）     1 个：/api/courses/public 0.36KB
游客材料页         2 个：/api/public/course + /api/content/doc   ← 按需
登录后任意页       bootstrap + 页面自己的接口（见上文的裁剪表）
```

## 二之二、按身份分档（不是一份全量发给所有人）

`GET /api/bootstrap` 原来不管谁调都返回同一坨（含分值表、班级名单、投屏状态、口令状态）。
现在按身份给不同档位：

| 字段 | 游客 | 学生 | 教师 | 为什么 |
|---|---|---|---|---|
| `lessons` | ✓ 2.1KB | ✓ | ✓ | 游客看课程材料也要课次清单 |
| `courses` | ✓ 0.1KB | ✓ | ✓ | 登录页/顶栏切课 |
| `classes` | ✗ `[]` | ✓ **只自己班** | ✓ 全部 | 学生切班下拉没有意义；名单统计不外传 |
| `items` | ✗ `[]` | ✗ `[]` | ✓ 4.6KB | 只有教师端班级页（记分表）用 |
| `scheme` | ✗ `null` | ✓ 概要 | ✓ | 学生侧栏要显示方案名 |
| `passwordIsDefault` | ✗ `false` | ✗ `false` | ✓ | **等于告诉任何人「直接试默认口令」** |
| `cast` | 移除 | 移除 | 移除 | 前端只有赋值、**没有任何地方读取**，但含投屏状态与局域网地址 |

结果：游客 2.2KB · 学生 2.5KB · 教师 7.3KB（原先是同一份 7.4KB）。

### 安全审计结论（用学生令牌和游客身份把所有教师接口试了一遍）

```
✓ 学生调教师接口        13 个全部 403（classes / scores / interact / presence /
                        rollcall / events / export / assignments / courses /
                        scheme/raw / edge-key …）
✓ 学生拿别的学生的数据   404 / 403（/api/students/:classId/:sid/score）
✓ 学生读讲义            403（仅教师）
✓ 跨学生用别人的作业 id  不可达（作业列表按自己身份过滤）
⚠ 已收紧                游客能看班级名单与人数、分值表、投屏局域网地址、口令是否默认
⚠ 保持开放              /api/content/asset 游客可读
                        —— 课程材料(materials)本来就是游客可见，它引用的图片必须能显示；
                           assets 目录应按「公开素材」对待，不要往里放只在讲义里出现的东西
ℹ 轻微指纹              /api/health 返回 node 版本与运行时
                        —— 内网系统、且 Docker HEALTHCHECK 依赖它，暂不动
```

## 三、刻意没动的

| 项 | 为什么 |
|---|---|
| `/api/classes/:id/scores` 仍然一次返回 `students + board + events` | 班级页要"名单、每人每项分值、最近记分流水"三样一起渲染，拆成三个接口会多 2 个 RTT，反而更慢 |
| `/api/bootstrap` 仍返回 `lessons`（2.1KB，20 课次） | 学生端材料页与教师端多处要课次清单；单开一个接口的收益小于多一次往返 |
| `events` 随 scores 一起返回（9.1KB） | 班级页底部要显示最近记分，且它带分页上限（1000 条），规模可控 |

## 四、还能继续做的（按性价比）

1. **`/api/pgsync` 去重**：`StudentLayout` 和 `PgWorkbench` 在代码练习页各拉一次。
   同步进行中时两次都会带回完整代码内容。做法：在 `usePgSync` 里做模块级单例（共用 in-flight Promise），两处调同一个 `resumeOnce()`。
2. **班级页分页/懒加载**：60 人 52KB 尚可；若某个班 150 人 + 每人 8 项，会回到 150KB 量级。
   可以先只返回"名单 + 总分"，展开某个学生时再取明细（点开才拉）。
3. **`/api/content/doc` 14KB**（单篇讲义正文）：一次只取一篇是对的，
   但材料页首屏若预取相邻课次会白拉——目前没预取，保持现状。
