# 教学机代理（局域网 → 公网）

教学机上有两块网卡：一块连**学生机的局域网**，一块通**公网**。
**课堂系统只部署在公网上**（那一份就是唯一的一份），教学机本机和局域网里都**不部署**课堂系统。
学生机在局域网里直接访问公网地址不稳 / 不通 —— 这个代理就在教学机上开一个端口，
把请求原样转给公网地址，顺带把静态资源缓存下来（省公网带宽）。

```
学生机（局域网）        教学机（只跑代理）              公网（唯一一份课堂系统）
┌──────────────┐  http://<教学机IP>:<端口>  ┌────────────┐  https  ┌──────────────┐
│ 浏览器        │ ────────────────────────▶ │ lan-proxy  │ ──────▶ │ 课堂系统      │
│              │                           │ + 缓存      │         │ 课程/班级/…   │
└──────────────┘                           └────────────┘         └──────────────┘
```

所以代理只干两件事：

1. **转发**：把学生机的请求原样送到公网地址（页面、接口、静态资源、投屏的 WebSocket 都一样）
2. **缓存**：把公开的静态资源缓存在教学机上 —— 第一个学生出公网，后面都本地命中
   （打开一次「代码练习」页就是 2.5MB；30 个学生各开一次 = 75MB 全走公网隧道，
   有了缓存只出 2.5MB）

> 代理**不做任何分流**：课堂系统只有公网那一份，投屏（`/ws`）、点名、在线状态
> 与页面走同一条路（都去公网）。

## 三、配置填什么

`proxy.conf` 是纯文本（`#` 开头是注释），要改的只有前两项：

| 键 | 填什么 | 例子 |
|---|---|---|
| `listen.port` | 学生机访问的端口 | `18799` |
| `listen.host` | 只监听某块网卡时填教学机局域网 IP；**留空 = 都听**（一般不动） | `192.168.5.226` |
| `target` | **必填**：公网上游地址 | `https://forum.r85269122.nyat.app:45600` |
| `tls.insecure` | 上游证书自签/过期时填 `yes`（跳过校验） | `no` |
| `timeout.ms` | 上游多久没回话算超时（毫秒） | `120000` |
| `log.verbose` | 填 `yes` 打印每条请求的状态码与耗时 | `no` |
| `cast.fanout` | 投屏扇出：公网下行从 N 份变 1 份（见「投屏扇出」一节） | `yes` |
| `cache.enabled` | 要不要缓存（见下面「缓存」一节） | `yes` |
| `cache.maxbytes` | 缓存最多占多少内存（字节） | `268435456`（256MB） |
| `cache.maxentries` | 最多缓存多少条 | `500` |
| `cache.ttl.assets` | 前端产物（带哈希）缓存多久（秒） | `31536000`（一年） |
| `cache.ttl.static` | 示例运行时库 / 图片缓存多久（秒） | `86400`（一天） |
| `cache.ttl.content` | 讲义 / 材料正文缓存多久（秒） | `60` |

改完**重启代理**才生效（关掉窗口再双击）。

## 四、不分流：所有流量都走公网

课堂系统只有公网那一份，所以代理不按路径分流 —— 页面、接口、静态资源、
投屏的 `/ws`（WebSocket）全部转给同一个上游。这样最省心，也不会有
「一半本地一半公网」导致的数据对不上的问题。

## 四点五、边缘端：数据分层（大流量本地走，实时状态聚合成快照上云）

代理不是单纯的转发器，它是一个**边缘端**：

```
学生机（局域网）              教学机（边缘端）                    公网（唯一一份课堂系统）
  浏览器 ──http──▶   缓存（静态资源/材料）+ 本地实时状态  ──聚合──▶  课程/班级/成绩
  浏览器 ──ws─────▶   投屏帧扇出（本地分给每个学生）    ──1 份──▶   投屏中继
```

| 数据 | 怎么走 | 省流手段 |
|---|---|---|
| 静态资源、课程材料 | **本地缓存** | 第一个学生出公网，其余本地命中（40 人共用一份） |
| 投屏画面 | 教师端 → 云端 **1 份**；云端 → 学生 **1 份** | 代理在局域网里扇出，公网只 1 份 |
| 在线状态 / 心跳 / 谁在看 | **聚合成一个快照请求** | 40 人 ≈ 10KB / 5 秒，而不是 80 条长连接 |

### 实时状态怎么上云（省流的关键）

学生的**到场通道**（`/ws?role=presence`）和**投屏观看**都在**局域网里**连着，
不往公网开连接。代理本地记下「谁在场、谁在看投屏」，
每 `edge.snapshot.interval` 秒打包成**一个**请求上报：

```json
POST /api/presence/snapshot
{ "source": "lan-proxy",
  "students": [ { "token": "<学生令牌>", "online": true, "casting": false }, … ] }
```

- **上报必须签名**（`edge.key`）：这个请求代表的是「一群人」，
  所以服务端要求 `X-Edge-Sign = HMAC-SHA256(edgeKey, source + 时间戳 + body)`，
  外加时间戳 ±5 分钟与「同一 source+ts 只收一次」。
  → 没有密钥的人**既不能伪造在线，也不能用一个空名单把全班踢下线**
- **身份以令牌为准**：签名过了之后，服务端还会逐个验条目里的学生令牌，
  班级/学号/姓名全由服务端从令牌解出来 → 条目里报的 sid 说了不算

#### 怎么拿到 edge.key

```bash
# 教师端（带教师令牌）
curl -H "Authorization: Bearer <教师令牌>" https://你的地址/api/teacher/edge-key
# → { "key": "39a92b…", "endpoint": "/api/presence/snapshot", "howto": "…" }
```

拿到后填进教学机的 `proxy.conf`：

```ini
edge.key = 39a92b…
edge.source = lan-proxy     # 可选，多台教学机时区分
```

> **升级顺序**：先升服务端 → 取到 key → 再升代理并填上。
> 代理没填 key 时不会静默失败：横幅会打
> `上报签名：**没配 edge.key** …`，日志里也会提示一次。
- 「不在快照里」的人 → 服务端立刻把他下线（不用等 120 秒 TTL）
- 服务端**只新增了这一个接口**，原有行为一个字没改
  （直连的学生照旧走原来的 WebSocket 通道）

**实测（3 个学生，代理出口在本机）**：

| | 原来（每人一条） | 现在（边缘端） |
|---|---|---|
| 代理到云端的长连接 | 6 条（3 presence + 3 student） | **2 条**（教师端 + 投屏帧管道） |
| 服务端看到的「谁在看投屏」 | 准 | **准**（快照如实上报） |
| 服务端看到的「谁在场」 | 准 | **准** |
| 有人退出观看 | 立刻 | 立刻（下一个快照周期） |

## 五、投屏（cast）怎么走代理

投屏的画面帧走 **WebSocket 二进制帧**：

```
教师端浏览器  ──ws://<教学机IP>:<端口>/ws?role=ctl────▶  代理  ──▶  公网课堂系统
学生观看页    ◀──ws://<教学机IP>:<端口>/ws?role=student──  代理  ◀──  （服务器广播）
```

代理对 WebSocket 是**原样字节转发**（不解析、不改写），所以投屏帧一字节不差地过去。
实测（真的连着那台课堂系统）：

| 检查 | 结果 |
|---|---|
| 教师端 → 代理 → 服务器 → 代理 → 观看端，一帧 300 KB | sha256 **完全一致** ✓ |
| 端到端延迟 | 约 100 ms 量级（帧率 15fps 时无感） |
| 连续 60 帧 × 64 KB（3.75 MB） | 字节一致，吞吐 ~94 MB/s |

### 教师端要「带白名单」打开

浏览器的抓屏（getDisplayMedia）只在**安全上下文**里可用：https、或 http://localhost、
或者用 `--unsafely-treat-insecure-origin-as-secure=<origin>` 显式加白名单。

所以**教师端如果走代理地址（http 的），必须用带白名单的 Chrome 启动**：

```bat
:: 用课堂系统自带的 打开教师端.bat，把 BASE_URL 填成代理地址即可
::   http://192.168.5.226:18799
:: 它会自动把这个 origin 加进白名单：
::   --user-data-dir=%LOCALAPPDATA%\ts-teacher-chrome
::   --unsafely-treat-insecure-origin-as-secure=http://192.168.5.226:18799
```

学生端（观看投屏）不需要特殊参数，直接打开代理地址即可。

### 「谁在看投屏」：每个真实观看者一条连接（服务端零改动）

服务端判断「谁在看投屏」是**按连接上的学生令牌**记账的（一条连接一个人）。
代理如果把 N 个人合并成一条，服务端就只认得一个人 —— 名不副实。

所以代理**为每个真实观看者各建一条上游连接，各带本人的令牌**：

```
教师端  ──1 条上游 ctl─────────────────▶ 服务器
学生① ──1 条上游 student（本人令牌）──▶ 服务器  ← 服务端按令牌如实登记
学生② ──1 条上游 student（本人令牌）──▶ 服务器
学生③ ──1 条上游 student（本人令牌）──▶ 服务器
                                        │
                      代理只取其中一条的帧 ┴──▶ 局域网分给所有本地学生
```

**好处**：

- **服务端一行都不用改**，行为与学生直连时完全一致
- 服务端看到的「谁在看」= **真的在看的人**；有人退出，代理就断掉他那条连接，
  服务端立刻不再算他（实测：关掉一个 → 服务端名单从 3 人变 2 人，没有幽灵观众）
- 伪造不了：令牌是服务端签发的，猜不出来
- 到场通道（presence）**逐条直连** → 「谁在场」也由服务端直接记

**代价（要知道）**：服务器会把帧广播给每一条 student 连接 →
**公网下行是 N 份**（不是 1 份）。代理只转发其中一份，其余丢弃。

| | 公网上行 | 公网下行 | 服务端看到的名单 |
|---|---|---|---|
| 代理（现在） | 1 份（教师端） | **N 份** | 准 ✓ |
| 学生各自直连 | N 份 | N 份 | 准 ✓ |

→ 弱网下必须用**差量模式 + 低帧率**（见下面的带宽提醒）。

投屏的帧要送到每个学生手上。**默认的做法**是每个学生各自一条 WebSocket 连到服务器，
于是服务器下行 = **N 份**（30 人看 ≈ 30 × 单份），全走公网隧道。

代理可以「扇出」：

```
默认：学生①…学生N ──N 条 WS──▶ 服务器 ──N 份下行──▶ 代理 ──▶ 学生
扇出：                            服务器 ──1 份下行──▶ 代理 ──▶ 局域网分给 N 个学生
```

**服务器那边一行都不用改** —— 它照旧给「学生连接」广播帧；代理用**一条**上游学生连接把帧接住，
再在局域网里分给所有本地学生。公网上行 1 份、公网下行 1 份。

实测（真的连着那台课堂系统，1 个教师端 + 3 个学生端）：

| 检查 | 结果 |
|---|---|
| 三个学生收到的帧 | sha256 **完全一致**（一字节不差） |
| 教师端看到的「几人在看」 | **3**（服务端按代理带来的名单自己算，代理不改写） |
| 端到端延迟 | 约 110 ms |

开关（`proxy.conf`）：

```ini
cast.fanout = yes    # 开：公网上行 1 份 / 下行 1 份
cast.fanout = no     # 关：退回「每个学生一条连接直连」（公网下行 N 份）
```

代理还会在自检里报告扇出状态：

```bash
curl http://127.0.0.1:18799/__proxy_stats
# "cast": {"fanout":true,"upCtl":true,"upStudent":true,"localTeacher":1,
#          "localWatchers":3,"uniqueWatchers":3,"frames":1,"framesToWatchers":3}
```

> **一个已知的小局限**：如果**教师端是直连服务器**（不走代理），教师端看到的「几人在看」
> 会是服务器视角的数字（1），而不是代理后面的真实人数（3）—— 代理改不了不经过它的连接。
> 帧本身照常正常。要数字准，就让教师端也走代理（用 `打开教师端.bat` 填代理地址）。

### 带宽提醒

> 因为每个观看者一条上游连接，**公网下行是 N 份** → 差量模式 + 低帧率是必须的：
> 30 人 × 8fps × 变化的块（一帧几 KB）≈ 1~2 Mbps，能扛；
> 全量模式（每帧整屏 100~200KB）30 人就是 24~48 Mbps，扛不住。

投屏帧会**经过公网隧道出去**，占公网带宽（一台机器 15fps 约 0.5~1 Mbps）。
人多的时候在教师端「课堂投屏」里把帧率降到 8 fps、质量调低一点即可
（判断标准：单台上行持续超过 0.8 Mbps 就降）。

## 六、系统里什么最耗资源（实测）

先量了一遍「一个学生打开一次代码练习页」要从公网拉多少东西（走公网隧道）：

| 资源 | 大小 | 说明 |
|---|---|---|
| `/examples/vue3-sfc-loader.js` | **1.76 MB** | 单页运行时库（SFC 编译器），最大头 |
| `/examples/vue.global.js` | **580 KB** | Vue 全局版 |
| `/assets/index-*.js` | 118 KB | 前端主包（带内容哈希） |
| `/vendor/marked.min.js` | 35 KB | 讲义里的 markdown 渲染 |
| `/assets/index-*.css` | 14 KB | 样式 |
| 首页 HTML + favicon + `playground/sfc-boot.js` | 22 KB | |
| **合计** | **2.50 MB** | 每个学生每次打开都重来一遍 |

**瓶颈不是服务器，是公网隧道的下行带宽**：这些文件的 `Cache-Control` 全是 `no-cache`，
所以浏览器每次都重新下载。30 个学生每节课各开一次 = **75 MB 全走公网**。

（顺带说明：真正吃服务器的是「扫目录 + 读 CSV」那部分，但一次页面加载只扫几个目录，
远小于 2.5MB 的下载量。所以先解决下载。）

## 七、缓存（代理 + 缓存，已默认开启）

**缓存在哪里：内存**（LRU，默认上限 **256MB**，`cache.maxbytes` 可调）。

- 不落盘、不写文件 → 代理一关就没了，重启后第一次访问要重新从公网拉
- 所以**建议教师机先自己打开一次学生端/代码练习页**，把大文件预热进缓存，
  后面学生打开就是本地命中（实测 1.76MB 那个文件：从 14 秒变 12 毫秒）
- 内存吃紧就调小 `cache.maxbytes`（比如 64MB）；机器内存大可以再调大（512MB / 1GB 都行）

代理在教学机上开一个**内存缓存**，只缓存**公开的 GET/HEAD**：

- **课程材料**（学生讲义）现在是公开内容（不需要登录）→ 可以缓存，缓存键里不带身份
- **讲义**（教师讲稿）→ 路径上就排除掉；上游还会回 `private, no-store`，代理看到就不存（双保险）
- 教师端 / 学生端接口 → 一律不进缓存

| 路径 | 缓存多久 | 为什么 |
|---|---|---|
| `/assets/*`（前端产物，文件名带内容哈希） | 1 年 | 内容变了就换文件名，可以永久缓存 |
| `/vendor/*`、`/examples/*`、图片 | 1 天 | 极少变 |
| `/api/content/doc?type=materials`（**课程材料**，公开内容） | 60 秒 | 老师改完课很快能生效 |
| `/api/content/doc?type=lecture`（**讲义**，教师内容） | **不缓存** | 教学公开原则：教师讲稿不进任何缓存 |
| 其它（`/api/teacher/*`、`/api/student/*`、`/ws`…） | **不缓存** | 个性化数据 / 长连接 |

另外它还会**改写 `Cache-Control`** 发给浏览器（`public, max-age=…`），
所以**浏览器自己也会把文件存到磁盘** —— 学生第二次打开代码练习页，浏览器直接用本地缓存，
连代理都不用问。

命中时会带上两个头，方便排查：

```
X-Cache: HIT   Age: 12
```

### 实测（30 个学生依次打开代码练习页，都走公网隧道）

| | 出公网的字节 | 总耗时 | 第 1 个学生 | 第 2 个 | 第 30 个 |
|---|---|---|---|---|---|
| 不开缓存 | 75.3 MB | 3457 ms | — | — | — |
| **开缓存** | **2.5 MB（省 97%）** | **683 ms** | 119 ms | **8 ms** | **12 ms** |

（客户端下载的字节数不变 —— 每个浏览器总得自己收一份；省下的是**出公网的流量**和**等待时间**。）

### 看缓存效果

```bash
curl http://127.0.0.1:18799/__proxy_stats
# {"ok":true,"cacheEnabled":true,
#  "cache":{"entries":8,"bytes":1963418,"maxBytes":67108864,"hits":203,"misses":7,"hitRate":0.97}, …}
```

### 缓存的边界（重要）

- **带令牌的请求不缓存**：教师端/学生端的接口都是个性化数据，缓存了就是串数据
- **只缓存 200**：403/404/5xx 都不进缓存
- **尊重上游的 `Cache-Control`**：上游说 `no-store` / `private` 的响应一律不存
- **讲义正文只缓存 60 秒**：老师改完讲义，学生最多 1 分钟后看到新内容（想立刻生效就把它调成 10 秒）
- 缓存在**内存**里：代理重启就没了（第一次访问重新出公网拉一次）
- 上限 256MB：够装下所有前端资源与示例运行时库（约 2MB），还有大把余量；
  超了按最近最少使用淘汰（`cache.maxentries` 默认 2000 条）

## 八、它做了什么（细节）

- **透传**：方法、请求体（含分块）、压缩（`Accept-Encoding` 原样带走）、响应体流式转发（不缓冲）
- **改写两处**：上游 `Location` 里的绝对地址 → 改成学生机看到的地址（否则 302 会把人甩到公网）；
  `Set-Cookie` 里的 `Domain=` → 去掉（否则学生机存不下 cookie）
- **补三个头**：`X-Forwarded-For` / `X-Forwarded-Proto` / `X-Forwarded-Host`（上游能看到真实客户端 IP）
- **WebSocket**：`/ws` 的升级握手自己拼报文、再双向转发（投屏画面帧与同步代码靠它）
- **错误分得清**：本机那侧连不上 → 提示「确认课堂系统在本机跑着」；公网那侧连不上 → 提示连不上上游
- **超时**：上游 `timeout.ms` 没回话 → 504

## 九、在场名单与「谁在看投屏」：都由服务端直接记

代理**不改写任何接口**，服务端看到的就是真实的：

| 内容 | 谁来记 | 说明 |
|---|---|---|
| **谁在场**（到场通道 `/ws?role=presence`） | 服务端 | 到场通道**逐条直连**（一个学生一条），名单最准。代价：40 人 = 40 条长连接 |
| **谁在看投屏**（`/ws?role=student`） | 服务端 | 代理**为每个真实观看者各建一条连接**（各带本人令牌）→ 服务端按令牌如实登记，**人数与名单都准**，且服务端零改动 |
| **几人在看**（教师端右上角） | 服务端 | 服务端自己算，代理不改写 |

> 代理曾经自己维护一份在场名单、再改写给教师端的接口 —— 那套已经**撤回**了。
> 现在代理只做两件事：**转发** 与 **缓存**。

**为什么投屏可以合成一条、到场不行**：
到场是「这个人在不在」，一条连接只能代表一个人，所以逐条直连；
投屏是「这些人在看同一块屏幕」，一条连接可以代表很多人（代理把名单带上即可）。


打不开 → 依次查：代理窗口还在吗 → 防火墙放行了吗 → `proxy.conf` 里的 `target` 对不对 → 公网那头服务在跑吗。

## 九点五、证书报错怎么办

报 **「本地受信任证书库中缺少该域名的根证书或中间证书」**（或英文
`CERTIFICATE_VERIFY_FAILED` / `unable to get local issuer certificate`）：

**原因**：代理连上游时校验证书，而上游用的是自签证书或证书链不全；
Win7 上内嵌 Python 读「本地受信任根证书库」本身就经常失败。

**解法**：在 `proxy.conf` 里把这一行改成 yes（**Win7 上建议就这么干**）：

```ini
tls.insecure = yes
```

然后重启代理。启动横幅里会有一行告诉你设置有没有生效：

```
  上游证书：已忽略校验（tls.insecure = yes）
  上游自检：OK（/api/health 返回 200）
```

> 以前这个开关「设了也没用」：老写法是先 `ssl.create_default_context()`
> （这一步就已经去读证书库了）才把校验关掉。现在设成 yes 时**根本不碰证书库**。
>
> 想严格校验又不想被 Win7 的证书库坑到，就用 `tls.cafile` 指一份 CA bundle。

**另外**：`proxy.conf` 用记事本存成 ANSI/GBK（Win7 默认）也没问题 ——
读不出的字符会被忽略，配置照样生效。但如果你改了配置却「像没改一样」，
看横幅里这行确认代理到底读到了什么：

```
    读到：port=18799 · target=https://… · tls.insecure=yes · cache=yes · 扇出=yes
```

## 九点八、弱网（随身 WiFi / 手机热点）下怎么配

实测结论（40 个学生同时开学生页）：

| 出口 | 静态资源 | 40 个真实浏览器 | 上游连接数 |
|---|---|---|---|
| **有线**（推荐） | 缓存命中 | **40/40 正常，P50 173ms** | 池内 8 条 + 扇出 2 条 |
| 随身 WiFi（Remote NDIS） | 缓存命中 | 前 10 个正常，**几十条并发后整条链路超时**（单连接也连不上，要等它自己恢复） | 同样 8+2 条，但链路本身扛不住 |

要点：

1. **缓存是第一道防线** —— 静态资源命中缓存后**根本不��公网**
   （1.76MB 的代码练习运行时：从 14027ms 变成 **12ms**）
2. **连接池是第二道** —— `upstream.pool = 8`：每个请求都新建连接 = 每个请求一次 TLS 握手，
   弱网上一次握手 600ms，40 个学生就是 40 次握手 → 必崩
3. **实时连接（WebSocket）也要收编** —— 每个学生 2 条长连接（到场心跳 + 看投屏），
   40 人就是 80 条；投屏那条代理已经做了扇出（`cast.fanout`），
   到场心跳那条还是逐连接直连，弱网下建议让教学机走有线
4. **出口网卡用 `bind.source` 指定**，但**优先用有线**：
   实测随身 WiFi 在几十条并发后整条链路超时（不是被拒绝，是直接不通）

```ini
# 推荐：出口走有线
bind.source = 192.168.5.226

# 缓存（必须开）
cache.enabled = yes
cache.ttl.html = 300        # SPA 入口页
cache.ttl.static = 86400    # 示例库
upstream.pool = 8           # 上游连接池
```

## 九点九、怎么自测（不用另外装任何东西）

文件夹里带了一个自检脚本，**只用 Python 标准库**，内嵌 Python 3.8 直接能跑：

```bat
:: 双击（最省事）
run-selftest.bat

:: 或者命令行（能看详细输出）
runtime\python\python.exe selftest.py
runtime\python\python.exe selftest.py --port 18799
runtime\python\python.exe selftest.py --n 40              :: 40 个学生同时开页
runtime\python\python.exe selftest.py --only cache,cast  :: 只跑某几项
runtime\python\python.exe selftest.py --list             :: 列出所有检查项
```

它做六件事，每项打「✓/✗ + 关键数字」，最后给总结：

| 检查项 | 看什么 | 期望 |
|---|---|---|
| `proxy` | 代理自检页 | 监听地址、上游地址对 |
| `upstream` | 公网通不通 | `/api/health` 200 |
| `cache` | 缓存有没有生效 | 第一次 MISS、第二次 **HIT** 且几毫秒 |
| `cast` | 投屏帧转发 | 发出与收到的帧 **sha256 一致** |
| `presence` | 在场通道直连 | 服务端直接记账 → 教师端看到的在线人数就是真的 |
| `load` | N 个学生同时开页 | 成功率、延迟 P50/P90 |

> 默认拿「名单里第一个学生」当测试账号（学号 `2515230114`）。
> 换机器上测就带上参数：
> `selftest.py --sid 你的学号 --name 你的姓名 --password 教师口令`

## 十二、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 启动器说找不到 python | 把内嵌 Python 解压到 `runtime\python\`，或装 Python 并加进 PATH |
| 启动器说找不到 proxy.conf | 复制 `proxy.example.conf` 改名为 `proxy.conf` |
| 窗口一闪而过 | 双击运行 bat（cmd 窗口才会停住）；或直接 `runtime\python\python.exe lan-proxy.py --config proxy.conf` |
| 学生机打不开 | 防火墙没放行；或 `listen.host` 填成了别的网卡 |
| 页面能开但图片/接口 404 | 上游地址（`target`）填错了 |
| 投屏卡 / 点名不动 | 投屏与点名都走公网（`/ws`），先看公网那头通不通；带宽不够时把代理的 `cache.ttl.static` 调大 |
| 上游证书报错 | `tls.insecure = yes` |
| 想临时改端口 | 命令行加 `--port 18800`（覆盖配置） |
| 要装第三方包 | 装到 `deps\` 目录即可（已在 `python38._pth` 的搜索路径里）；不过本脚本不需要任何第三方包 |
| 学生说代码练习页打开慢 | 多半是公网带宽被占；看 `/__proxy_stats` 的命中率（越高越好），必要时把 `cache.ttl.static` 调大 |
| 老师改了讲义，学生还是旧的 | 讲义正文缓存 `cache.ttl.content` 秒（默认 60）；改完等一分钟，或把它调小 |
