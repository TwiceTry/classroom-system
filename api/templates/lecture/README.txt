讲义模板（lecture/ = 教师讲稿）

一、这一份是什么
--------------
教师向：怎么教。包含学生材料的全部内容 + 讲法。学生看不到这一份。

二、和另外两样的对应（三方职能约定）
--------------------------------
  第NN课-XXX 这个名字，在三个地方必须一模一样：
      lecture/第05课-响应式.md      ← 教师讲稿（本目录）
      materials/第05课-响应式.md    ← 学生讲义
      代码示例/第05课-响应式/        ← 可运行实例
  补充课不占课次编号，统一叫 补充-XXX（如 补充-JS基础复习），三处同名。

三、结构（每篇固定）
----------------
  # 第NN课 · 标题（教师讲稿）
  ## 📅 教学信息 / 🎓 素质目标 / 📖 知识目标 / 🛠 能力目标
      🔑 教学重点 / 🧗 教学难点 / 🇨🇳 思政融入点 / 📝 作业      ← 元信息块
  ## 一个知识块
      ### 📺 屏幕   …（学生屏幕上要出现的内容，就是材料里同名小节，逐字对齐）
      ### 🎤 讲稿   …（怎么讲：提问 / 易错预警 / 演示动作）
  ## ⏱️ 时间分配总览（90 分钟）
  ## 📝 课后记（教学反思 · 课后填写）
  · 每个知识块的「屏幕」与「讲稿」必须配对（个数相等）
  · 时长、提示写在标题下面一行的引用块 > …，不要塞进标题

四、讲义 ↔ 材料 的同步规则（小节锚点约定）
------------------------------------
  1) 同一个节点的两侧标题，写成**同一个**（逐字一致，忽略行内标记 / 全角半角冒号 /
     括号形状 / 空白 / 英文大小写；emoji、用词、标点不忽略）
  2) 讲义里带 ### 📺 屏幕 的节，材料里必须有同名标题 —— 📺 就是「这节要给学生看」的开关
  3) 一屏讲完：正文 ≤ 900 字、代码块 ≤ 3 个、表格 ≤ 12 行；超了就在**两侧同时**下沉一级
      讲义：#### 细节点（写在 ### 📺 屏幕 之内）
      材料：### 细节点
     匹配只看标题，不看层级；所以两侧层级不同是正常的

五、常见错法
----------
  · 只在材料里拆 ###，讲义没跟着拆 → 那个子节点材料独有，讲义里滚到那儿只能跳到上一级
  · 讲义里用 ### 当细节点 → 和 ### 📺 / 🎤 冲突，不生效（细节点必须用 ####）
  · 两侧子标题措辞不同（「各管什么」vs「分别负责什么」）→ 视为不同节点，不同步
  · 给教师专属节（时间分配、课后记）写 ### 📺 → 系统会要求材料也有同名节

六、改完怎么自证
------------
  cd 课堂系统
  node server/check-sections.js           只报错与超标清单
  node server/check-sections.js --report  生成一份可勾选的待改清单

  看到「错误 0」即两侧对齐；软约束列表里没有你这节课，说明没有超一屏的叶子节点。

七、导入
------
  讲义页 → 导入讲义（根目录就是这些 .md，别再套一层文件夹）
  「合并」只增改；「整体替换」会把本地多出来的讲义移进 data/.trash/（可捞回）。
  讲义和材料是两份文件：只导讲义不会动材料，两份都要更新就各导一次。

八、完整规范
----------
  course-content/小节锚点约定.md     小节怎么拆、怎么和材料对齐
  course-content/三方职能约定.md     三件套各自的职能与禁止项
